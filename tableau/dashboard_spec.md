# Tableau 대시보드 설계

> 상태: 설계 완료, Tableau 구현·Public 게시 전. `.twbx`와 공개 URL이 생기기 전까지 완성 산출물로 표기하지 않는다.

## 1. 전달할 메시지

이 대시보드는 숫자 카드를 나열하지 않는다. 사용자가 다음 흐름을 따라 근거와 한계를 함께 읽게 한다.

1. 매출은 어떤 고객군에 집중되는가?
2. 첫 구매 후 어느 월차에 다시 구매하는가?
3. 구매 고객의 전체 기간 거래 활동 수준은 어떻게 분포하는가?
4. 쿠폰 사용 고객의 차이는 얼마나 크며, 비교의 신뢰 한계는 무엇인가?

제목은 **이커머스 고객 분석 — 매출 집중에서 재구매 실험까지**로 한다. `인과추론`, `LTV`, `가입 funnel`은 제목과 KPI에서 제외한다.

## 2. 화면 구조

Desktop 1,400 × 1,050, 세로 스크롤 없이 2×2의 동일 크기 차트로 구성한다.

```text
┌─────────────────────────────────────────────────────────────┐
│ 제목 · 분석기간 · 데이터 범위 · 정의 보기 링크                │
├────────────────────────────┬────────────────────────────────┤
│ 1. 세그먼트 매출 집중도     │ 2. 첫 구매월 코호트 히트맵       │
│ 정렬 막대 + 누적 비중        │ 월차별 리텐션 + 코호트 크기       │
├────────────────────────────┼────────────────────────────────┤
│ 3. 거래 활동 단계           │ 4. 쿠폰 관찰 차이 + 균형 진단     │
│ 중첩 집합 막대               │ forest plot / SMD dot plot       │
├─────────────────────────────────────────────────────────────┤
│ 한계 3줄 · 데이터 출처 · GitHub 링크                          │
└─────────────────────────────────────────────────────────────┘
```

상단에 총 고객·총매출 같은 KPI 카드를 별도로 두지 않는다. 각 숫자가 어느 관계에서 나온 값인지 차트 안에서 직접 보이게 한다.

## 3. 시트 설계

### 3.1 세그먼트 매출 집중도

- 형태: 매출 비중 내림차순 가로 막대
- 색상: 성장형·핵심 파트너만 강조, 나머지는 회색
- 라벨: 세그먼트, 고객 수, 관측 매출, 매출 비중
- 보조선: 상위 2개 누적 68.3%
- 주석: `Monetary`가 RFM 분류 변수이므로 독립적 성과 검증이 아님
- 금지: 도넛 차트, 미래 LTV 표현

데이터: `data/derived/segment_revenue_share.csv`

### 3.2 첫 구매월 코호트 리텐션

- 형태: y축 `first_purchase_month`, x축 `month_index`, 색상 `retention_pct`
- 라벨: 리텐션 %, tooltip에 `cohort_size`, `month_index`
- 색상 범위: 0~30%, 100%인 m0는 별도 중립색 또는 표시 제외
- 미관측 월: 공백·회색, 관측했지만 구매가 없으면 0%
- 주석: 첫 구매월은 회원 가입월이 아니며 마지막 코호트는 관측기간이 짧음

데이터: 공개 구현에는 `tableau/data/cohort_retention_long.csv`, BigQuery 연결에는 `sql/03_purchase_cohort_retention.sql`의 long-format 결과를 사용한다.

### 3.3 거래 활동 단계

- 형태: 고객 수 내림차순 가로 막대
- 단계: 거래 고객 → 거래ID 2개 이상 → 거래ID 5개 이상 → 우선 관리 세그먼트
- 라벨: 고객 수와 전체 거래 고객 대비 비율
- 주석: 중첩된 전체 기간 분류이며 시간 순서 funnel이 아님
- 금지: `가입`, `첫 구매 전환`, `재구매 전환` 명칭

데이터: `data/derived/activity_ladder_summary.csv`.

### 3.4 쿠폰 관찰 차이와 균형 진단

상단은 outcome별 평균 차이와 bootstrap 95% CI를 보여주는 forest plot으로 만든다.

- 방법: 단순 차이 / 72쌍 매칭 차이
- outcome: 60일 재구매율 / 60일 상품매출(수량 × 단가, 배송·세금 제외)
- 0 기준선 필수
- 제목과 tooltip에서 `ATT`, `인과효과` 사용 금지

하단 또는 tooltip에는 매칭 전·후 공변량 SMD를 보여준다.

- x축: standardized mean difference
- 기준선: `±0.1`
- 메시지: 매칭 후에도 16개 중 6개가 기준 밖

outcome 데이터: `data/derived/matched_effects.csv`, 균형 진단 데이터: `data/derived/matched_balance.csv`.

## 4. 필터와 상호작용

세 CSV는 서로 다른 집계 단위이므로 전역 `Apply to all worksheets`를 사용하지 않는다.

| 필터 | 적용 대상 | 이유 |
|---|---|---|
| 세그먼트 | 세그먼트 매출 시트만 | 다른 집계 파일에 동일 차원이 없음 |
| 첫 구매월 | 코호트 시트만 | 코호트별 관측 가능 기간이 달라짐 |
| outcome·method | 쿠폰 시트만 | 매칭 결과 전용 차원 |

활동 단계에는 필터를 두지 않는다. 독립 데이터 소스 간 억지 관계나 blending을 만들지 않는다. 차트 클릭은 highlight만 허용하고 다른 시트의 분모를 바꾸지 않는다.

## 5. 색상·형식

- 본문: `#263238`, 제목: `#17324D`
- 강조: `#E07B5B`, 비교: `#4A90D9`, 비강조: `#A7B0B8`
- 격자: 최소화, 배경: 흰색
- 한글 폰트: Noto Sans KR 또는 NanumGothic
- 소수점: 비율 1자리, 금액 정수 또는 `$1.58M`
- 모든 tooltip에 분모와 분석 단위를 명시
- 적록 팔레트를 피하고 색만으로 상태를 구분하지 않는다

## 6. 구현 순서

1. BigQuery Standard SQL 기준으로 `00`→`04` 현재 파이프라인을 실행한다.
2. `make tableau-data`로 비식별 Tableau 연결 데이터를 생성한다.
3. 각 파일을 독립 데이터 소스로 연결한다.
4. 시트 4개를 먼저 만들고 제목·축·tooltip의 정의를 검수한다.
5. 대시보드에 배치한 뒤 1,200px 너비에서도 라벨이 잘리지 않는지 확인한다.
6. Tableau Public 게시 후 공개 URL·업데이트 날짜를 README에 추가한다.

## 7. 게시 전 체크리스트

- [ ] ‘가입월’, ‘가입→첫 구매’, ‘ATT’, ‘인과효과’, ‘예측 LTV’ 표현이 없음
- [ ] 활동 단계의 91.49%를 이탈률 8.51%와 혼동하지 않음
- [ ] 코호트의 0과 미관측이 다른 색/상태로 보임
- [ ] 쿠폰 차이에 CI와 잔여 불균형 경고가 함께 보임
- [ ] 각 시트의 집계 단위와 분모가 tooltip에 있음
- [ ] 필터가 호환되는 시트에만 적용됨
- [ ] 원본 고객·거래 행을 Public 워크북에 포함하지 않음
- [ ] 모바일/작은 화면 미리보기와 색각 접근성을 확인함
- [ ] GitHub README의 수치·차트와 일치함
